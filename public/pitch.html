ConSSS Wars × 0G：可驗證的敵方指揮官

《鏈之迴響》— 0G Taipei Hackathon 2026-09-07 · 賽道 A 可驗證推理 ＋ 賽道 B 有身份的 Agent

做了什麼

把《鏈之迴響》裡腳本化的敵方 Boss AI，換成一個持有 0G Agentic ID 的指揮官 Agent，它每回合的決策都經 0G Compute Router 推理，並封成一枚任何人都能驗證的印章。

解決什麼問題

過去玩家的鏈上戰績要靠我方伺服器自簽的 voucher 才發得出去，玩家必須先相信 ConSSS 沒作弊；現在「AI 判了什麼」變成 TEE 簽出、可獨立驗證的事實，不需要相信我們。

架構是什麼

Godot 遊戲端在玩家回合開始就預取指揮官決策（把 LLM 延遲藏進玩家思考時間）→ Cloudflare Pages Function /agent/decide 打 0G Router（0gm-1.0-35b-a3b、verify_tee: true）→ 把 x_0g_trace.tee_verified、provider 地址與 Agentic ID 封成印章（sha256 ＋ HMAC）→ /agent/verify 與 /verify 頁面離線逐章驗證。

Why build on 0G

只有 0G 同時給我們「一行 base_url 就能用的 OpenAI 相容 Router」、「TDX TEE 硬體證明的推理」與「ERC-7857 的 Agent 鏈上身份」，讓遊戲 AI 的每個判斷都能歸責到一個有身份、有證明的 Agent。

Demo 完成了什麼

本機打完一場 Boss 戰，每回合的指揮官思路與印章 hash 顯示在預告 UI 上，結算按「驗證這場戰鬥」逐章亮綠；印章帶真實的 tee_verified: true 與鏈上 Agentic ID 0xC1Af…0d97:1，網路拔掉時遊戲仍能用確定性 AI 打完。

未來 Roadmap

把印章從「AI 判斷可驗證」延伸到「整場戰鬥可驗證」：server 重播或 zk-proof 驗證結算公式、用 ZG-Res-Key 向 provider 二次核對 TEE 簽名、印章寫進 0G 鏈成為 On-Chain Agent（賽道 C）、Agentic ID 的智慧內容改存 0G Storage 加密 blob。
