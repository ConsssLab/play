ConSSS Wars × 0G：可驗證的敵方指揮官

《鏈之迴響》— 0G Taipei Hackathon 2026-09-07 · 賽道 A 可驗證推理 ＋ 賽道 B 有身份的 Agent

做了什麼

把《鏈之迴響》裡腳本化的敵方 Boss AI，換成一個持有 0G Agentic ID 的指揮官 Agent，它每回合的決策都經 0G Compute Router 推理，並封成一枚任何人都能驗證的印章。

解決什麼問題

過去玩家的鏈上戰績靠我方伺服器自簽的 voucher 才發得出去，玩家必須先相信 ConSSS 沒作弊；現在「敵方 AI 每回合的決定」有 TEE 簽名與 Agentic ID 可查，官方無法事後竄改或偽造——這一步先讓 AI 判斷不可作惡，整套結算公式不可作惡是 Roadmap 的 server 重播／zk。

架構是什麼

Godot 遊戲端在玩家回合開始就預取決策（把 LLM 延遲藏進玩家思考時間）→ /agent/decide 跑兩個 Agent：偵察官讀盤面出簡報、指揮官做決定，兩跳都經 0G Router（0gm-1.0-35b-a3b、verify_tee）並各封一枚章串成證明鏈 → 每枚章由 Agentic ID 持有者錢包 EIP-191 簽名，並封入 provider 在 TEE 內的簽名 → /verify 頁 ecrecover 對照鏈上 ERC-7857 與 ERC-8004 的 ownerOf，離線、免 gas。

Why build on 0G

只有 0G 同時給我們「一行 base_url 就能用的 OpenAI 相容 Router」、「TDX TEE 硬體簽名的推理」與「ERC-7857 ＋ 官方 ERC-8004 的 Agent 鏈上身份」，讓遊戲 AI 的每個判斷都能歸責到一個有身份、有證明的 Agent。

Demo 完成了什麼

本機打完一場 Boss 戰，每回合偵察簡報、指揮官思路與印章 hash 顯示在預告 UI，結算一鍵開瀏覽器逐章亮綠；每枚章帶真實的 tee_verified: true、provider TEE 簽名、ERC-7857 Agentic ID 0xC1Af…0d97:1 與 ERC-8004 agentId 396；網路拔掉時遊戲仍能用確定性 AI 打完。

未來 Roadmap

把印章從「AI 判斷可驗證」延伸到「整場戰鬥可驗證」：server 重播或 zk-proof 驗證結算公式、每場戰鬥的印章 Merkle root 寫進 ERC-8004 Reputation Registry 成為 On-Chain Agent（賽道 C）、Agentic ID 的智慧內容改存 0G Storage 加密 blob。
